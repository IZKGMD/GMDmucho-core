# MuchoCore на VPS: быстрая установка и обновление

Для Ubuntu VPS с доступом администратора. Полная PHP 8 версия требует PHP 8.2+ и MariaDB; при установке через Docker зависимости настраиваются автоматически.

## Новый VPS (тестовая версия из main)

Запусти от своего SSH-пользователя с правом sudo:

```bash
curl -fsSL https://raw.githubusercontent.com/IZKGMD/GMDmucho-core/main/install-remote.sh -o /tmp/muchocore-install.sh && sudo bash /tmp/muchocore-install.sh --ref=main
```

`main` — **разрабатываемая версия**, а не опубликованный стабильный релиз.
Для обычного публичного сервера используй опубликованную стабильную версию;
после её выпуска достаточно убрать `--ref=main`.

Установщик проверяет среду, запрашивает параметры домена, поднимает сервисы и
предлагает создать администратора в защищённой форме браузера. После установки
зайди на `https://ТВОЙ-ДОМЕН/admin/` и выполни первоначальную настройку.
Не передавай пароли, SSH-ключи или содержимое `.env` через чаты и GitHub issues.

## Обновление уже работающего VPS — одна команда

```bash
sudo mucho update
```

Затем:

```bash
sudo mucho doctor
```

Если команда `mucho` отсутствует, перейди в установленную директорию
(по умолчанию `/opt/mucho-core`) и запусти `sudo ./update.sh`.

Обновление сохраняет конфигурацию и постоянные Docker volumes. Перед
обновлением реального сервера рекомендуется проверенная резервная копия
SQL, `.env`, `.secrets` и Cloud Save key. Новая установка и обновление —
**разные операции**: не запускай установщик заново для обновления.

Если `update.sh` сообщает о локальных изменениях отслеживаемых файлов,
он **намеренно остановится**. Не удаляй правки через `git reset --hard`
без анализа. Сначала перенеси нужные изменения в GitHub (как обычный PR)
или создай проверяемый резервный патч. После этого верни сервер к чистому
основному дереву и используй одну команду обновления.

## Минимальная проверка

```bash
curl -fsS https://ТВОЙ-ДОМЕН/health
```

Ожидаемый ответ: `1`.

Также проверь `/admin/`, `/dashboard/` и фактическую работу патченного
клиента Geometry Dash. HTTP 200 и зелёные CI не равны сертификации GD 2.209.

## Если что-то пошло не так

1. Не сноси контейнеры с `-v` и не удаляй тома базы данных.
2. Проверь `sudo mucho doctor` и состояние Docker.
3. Сохрани логи и текущий Git SHA; не публикуй приватные данные.
4. Применяй восстановление только из проверенной резервной копии,
   учитывая новые записи в базе после обновления.
