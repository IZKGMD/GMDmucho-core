# MuchoCore — принципы

> **Простота и надёжность.**

## Как пишем код

1. Сначала простое решение.
2. Не добавляем новый класс или систему, если можно обойтись существующей.
3. Один файл — одна понятная задача.
4. Ошибка должна быть видна в логах, а не тихо теряться.
5. Не ломаем старые Geometry Dash endpoints без необходимости.
6. Секреты не храним в исходниках.
7. Любой важный фикс получает тест.

## Как добавлять новую функцию

```text
GD request
   ↓
Controller
   ↓
Service
   ↓
Repository
   ↓
Database
```

Не нужно строить дополнительный слой, если текущей цепочки достаточно.

## Правило для исправлений

Сначала исправляем причину.
Потом добавляем маленький тест.
Потом запускаем CI.
Только после этого изменение попадает в main.

## Правило для базы

Старые миграции не переписываем.
Для изменения существующей схемы создаём новую миграцию.

## Правило для совместимости

GDPS должен продолжать отвечать старым клиентам там, где это возможно.
Совместимость важнее красивого рефакторинга.
